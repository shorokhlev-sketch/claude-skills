# 03 - Pipeline: concept -> frames -> i2v -> assembly

End-to-end воркфлоу визуальной кампании. Роли: **фото - я (Higgsfield CLI), видео - я (Higgsfield CLI, Seedance и другие модели), монтаж - я (Palmier MCP)**. Пользователь - арт-директор: принимает кадры и клипы, задаёт правки.

## Этапы

1. **Концепт + каденс-грамматика.** Зафиксировать мотив, мир (напр. брутализм/бетон), список лук/кадров и кат-лист (ритм). Референс-кампанию можно разобрать на каденс. Хранить в `<campaign>/PROGRESS.md` (живое состояние, кат-лист, инвентарь) + `RUN.md` (launch-файл сессии).
2. **Первые кадры (я).** По `01_prompt-craft.md` + `02_higgsfield-routing.md`. Пошагово, self-QC через Read, принимать каждый. Скачивание -> `~/Downloads/` (staging), **принятый кадр сразу копировать в `<campaign>/firstframes/`** (постоянное хранилище - пользователь чистит Downloads/Корзину, кадры пропадают), инвентарь -> `firstframes/MANIFEST.md`.
3. **i2v-промпты.** skill `seedance` + `00_seedance-rules.md` + модули (НЕ по памяти). Писать в `<campaign>/seedance-prompts.md`: `Starting from the provided first frame, hold that exact composition and framing, do not reframe or crop.`, aspect = формат кампании (из опросника), аудио OFF, камера обычно locked (двигается субъект/материал). Face-lock (3 constraint-блока) только на кадрах с лицом. Имена стиллов под каждым клипом держать в актуальном состоянии.
4. **Генерация видео (я).** Гоню сам через `higgsfield generate create <video_model>` с принятым кадром как `--start-image`, результат забираю `cli.js grab` в `<campaign>/inbox/`. Модель выбираю по бюджету (`02_higgsfield-routing.md` -> «Видео: цена вопроса»): черновая проверка движения - дешёвой моделью, финал - Seedance 2.0. Перед каждым прогоном сверяюсь с балансом (`higgsfield account status`).
5. **Монтаж (я).** skill `palmier-edit` - импорт клипов, сборка по каденс-грид, диссолвы/склейки, исходный звук в ноль, холст по формату.

## Harness (повтор, жёстко)

- ДВЕ заглавные буквы в начале каждого сообщения.
- Видео-промпты - только после чтения seedance-доков.
- Фото и видео генерю я; решения/промпты - не из головы. Кредиты не жечь: сначала дешёвый черновик, дорогая модель - на принятый вариант.

## Файлы кампании (конвенция SECOND NATURE)

```
<ai-visual-root>/<campaign>/
  RUN.md              - launch-файл сессии (прочитал -> сразу работаешь)
  PROGRESS.md         - живое состояние, кат-лист, инвентарь, уроки, next
  STORYBOARD.md       - раскадровка / кат-лист (если campaign film)
  ENV-LOCK.md         - залоченная среда: verbatim ENV/INTERIOR-блоки + рефы (при multi-shot)
  TROUBLESHOOT.md     - журнал проблем и решений серии (уроки -> потом в скиллы)
  storyboard.json     - МАШИННЫЙ сториборд: кадры ката + рефы + промпты + статусы + световые карточки (источник истины для tools/storyboard)
  seedance-prompts.md - i2v-промпты с актуальными именами стиллов (человекочитаемый архив; рабочие промпты - в storyboard.json)
  refs/               - внешние рефы
  videos/             - принятые i2v-клипы (<shotId>.mp4)
  firstframes/
    MANIFEST.md       - инвентарь принятых кадров
    *.png             - КОПИИ принятых кадров (постоянное хранилище; Downloads - staging)
```

**Сториборд-приложение:** `<ai-visual-root>/tools/storyboard/` (`node server.js` -> http://127.0.0.1:4646) - живой сториборд по `storyboard.json` (SSE). Статус-пайплайн кадра: `frame-todo -> frame-review -> prompt-todo -> prompt-ready -> video-queued -> video-generating -> video-review -> video-approved -> uploaded`. Я веду статусы в json; пользователь оценивает в UI. Генерация видео - через Higgsfield CLI (`higgsfield generate create <video_model> --start-image <кадр>`, см. `02_higgsfield-routing.md`), клипы -> `videos/`; одобренные - в Palmier через MCP `import_media`.

**Поле `light` у шота** - световая карточка сцены (см. Континуити п.2), строка формата `источник · направление+высота · температура/грейд · контраст`. Заполняется до генерации первого кадра сцены и копируется всем шотам той же сцены без изменений. Патчится так же, как остальные поля:

```
node <ai-visual-root>/tools/storyboard/cli.js set <shotId> --light "available daylight · frontal, flat · neutral-cool muddy grade · ~2:1"
```

**ENV-LOCK-блоки - только чистый английский.** Всё, что помечено «вставлять дословно», не должно содержать русских фраз/заметок - иначе они утекают в промпт. Русские комментарии - отдельными строками вне цитаты.

## Континуити (критично для multi-shot / campaign film)

Самая частая поломка - кадры красивые поодиночке, но НЕ клеятся (разная геометрия комнат, стены, свет). Лечение - цепочка промежуточных рефов:

1. **Канонический ассет первым.** Генерь опорный кадр локации/комнаты/тела/персонажа (напр. кадр проходки = эталон коридора; интерьер комнаты = эталон мира модели). Дальше всё производное делай с НИМ как `--image`-рефом.
2. **Световая карточка сцены - до первого кадра.** Свет ломает монтаж быстрее геометрии: два кадра одной комнаты с ключом слева и справа не склеятся никогда. Поэтому на КАЖДУЮ сцену фиксируется карточка из четырёх полей и дальше не меняется:

   `источник · направление+высота · температура/грейд · контраст (key:fill)`

   Например: `available daylight · frontal, flat, no visible source · neutral-cool, muddy desaturated grade · low contrast ~2:1`.

   Карточка живёт в поле `light` шота в `storyboard.json` (см. «Файлы кампании» выше) и дословно вклеивается в каждый промпт сцены. Производные кадры сцены берут свет НЕ словами, а relight-lock с канонического рефа (`01_prompt-craft.md` -> «Relight-lock»). Расходится карточка - расходится кат.

3. **Геометрия должна совпадать между связанными планами.** Если в peek/глимпсе за моделью виден кусок её мира (вода/золото/окно), её полный «интерьер» обязан показать ТУ ЖЕ комнату: те же стены, размер, окно/перегородка/проём, свет. Бери peek как реф для интерьера (и наоборот).
4. **Стены/материал/свет - от реального кадра локации.** Станции, комнаты, прибытие - все с рефом коридора-проходки, чтобы мир был один.
5. **Реальная геометрия важнее «красивого кадра».** Узкая каморка с маленьким окном и боковым проходом должна остаться узкой каморкой во всех планах, а не превратиться в просторный зал. Снимай геометрию с принятого кадра и держи её.
6. **Двери/проёмы:** вдоль боковой стены (плоская стена ∥ камере), не тоннель-в-торце; ключевую комнату - в конце. Иногда проём в интерьере лучше НЕ показывать вовсе (чище мир).

## Анти-грабли (быстрый чек перед генерацией)

- **Свет закрыт по формуле и совпадает со световой карточкой сцены** (см. 01 -> «Свето-чек», и Континуити п.2). Это первый пункт не для порядка: промах по свету дороже промаха по гардеробу.
- Если кадр производный от рефа - в промпте стоит relight-lock (см. 01).
- Материал = костюм на модели, не плоть и не swatch (см. 01).
- Лицо крупно/фронтально или бери nano_banana с рефом (см. 02).
- safe-блок где материал у тела; следи за NSFW.
- Перегон - 1-2 фактора за раз; имена версий не путать.
- Перед сборкой проверь fps/формат таймлайна (palmier-edit) - не гадай.

## Видео: по одному клипу, роль кадра решается индивидуально (правило пользователя, 2026-08-31)

**Цикл одного клипа - три шага, ворота на каждом (правило пользователя, не срезать):**
1. **выбрать кадр** - предложить, какой шот оживляем, дождаться согласия;
2. **согласовать промпт** - показать промпт пользователю ЦЕЛИКОМ в чате и дождаться «ок». Это отдельные ворота: даже когда пользователь сказал «на твоё усмотрение», «делай быстрее» или «сам решай» - это про выбор кадра и раскладку, а НЕ разрешение гнать видео без показа промпта;
3. **только потом запускать.**

Кредиты тут ни при чём: клип стоит 22.5, но переделка стоит ещё и времени пользователя на просмотр брака, а половина правок видна прямо в тексте промпта до генерации.

**Гнать строго ПО ОДНОМУ клипу.** Не ставить пачку в очередь: каждый клип показывается пользователю, обсуждается и принимается или бракуется отдельно, и только потом запускается следующий. Пачка съедает кредиты на повторении одной и той же ошибки во всех клипах сразу - так мы потеряли два клипа на Mini (в одном не читался дрейф, в другом плыл фон) и два на 2.0.

**Роль кадра - старт или финал - решается для КАЖДОГО кадра отдельно.** Общего правила вида «станции всегда финал, проходки всегда старт» нет и не заводить: пользователь отказался от такого обобщения. Спрашивать или предлагать под конкретный кадр.

- кадр как СТАРТ (`--start-image`): движение уходит из утверждённой композиции;
- кадр как ФИНАЛ (`--end-image`): движение приходит в утверждённую композицию и замирает в ней. Работает на `seedance_2_0`, проверено. В промпте роль назвать дословно: `The provided image is the FINAL frame of this shot: the movement resolves exactly into that composition and the last frame matches it precisely.`

**Уроки по движению (оба выстраданы на браке):**
- Амплитуду называть числом. `almost imperceptibly`, `a few degrees` -> модель делает движение нечитаемым. `rotates about twenty degrees`, `drifts by the width of her own body` -> читается.
- Если герой должен ПОКОИТЬСЯ - запрещать движение перечислением, иначе выйдет барахтанье: `does not swim, does not paddle, does not thrash, does not drift, does not rotate; completely passive and inert, position in frame identical at start and end`. Двигать в таком кадре только среду (вода, сквозняк, пыль).
- Фон прибивать явным блоком, иначе Seedance «оживит» стены: перечислить, что именно стоит намертво (стены, косяки, проёмы, светильник, пол), и добавить `no warping or morphing of the background` + `no new objects appear in frame at any time` (лечит вылезающие из ниоткуда предметы).

## Хранение и имена файлов (обязательно, с 2026-08-24)

**Проблема, которую это лечит:** файлы терялись. При `accept` кадр переезжает `inbox/` -> `firstframes/`, и ссылки на старый путь ломались; а имена вроде `pk3_copper.png` ничего не говорили ни пользователю, ни мне - в папке на 60 файлов нужный кадр не находился глазами.

**Правило: имя файла = адрес шота.**

```
firstframes/<shotId>__v<N>__<модель>.png
```
`v1` - принятый кадр (со звездой), дальше вариации по порядку. Модель в имени - чтобы видеть, чем снято, без залезания в json.
Пример: `porcelain_peek__v2__seedream-v5-pro.png`.

**Папки:**
- `firstframes/` - кадры, привязанные к шотам (принятые и вариации). Только этот слой попадает в кат.
- `refs/` - исходные рефы пользователя, env-рефы, запасные ракурсы. Не кадры ката.
- `inbox/` - транзит: сюда падает всё скачанное (`cli.js grab`, перехват Downloads), отсюда разбирается. Не хранилище.
- `.trash/` - снятое с производства. Обратимо, не `rm`.

**Инструмент:**
```
node <ai-visual-root>/tools/storyboard/tidy.js [--campaign <slug>] [--dry]
```
Переименовывает принятые кадры по конвенции, обновляет ссылки в `storyboard.json` и `canvas.json`, чинит битые пути на холсте (файл переехал), генерит `firstframes/MANIFEST.md` - человекочитаемый индекс «шот -> файл -> статус». Идемпотентен, `--dry` показывает план без изменений.

**Когда гонять:** после каждой серии приёмок и обязательно перед тем, как показывать холст пользователю. Дёшево и чинит рассинхрон до того, как он его увидит.

**MANIFEST.md** - точка входа для человека: открыл, увидел все шоты, статусы и имена файлов. Автогенерируется, руками не править.
