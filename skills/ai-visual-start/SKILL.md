Запусти визуальный воркфлоу (AI-visual продакшн).

## Шаг 0 - Подтяни скиллы и harness (молча, до опросника)

Прочитай скилл `ai-visual` (SKILL.md + `01_prompt-craft.md` + `02_higgsfield-routing.md`) и `seedance`. Если сессия клиентская (режим «Клиентский заказ» или разговор про цену/сроки/правки/сдачу) - ещё и `04_client-workflow.md` + `<ai-visual-root>/client/PROCESS.md`. Соблюдай harness:
- каждое сообщение с ДВУХ заглавных букв («ГОтово», «СДелал»);
- видео-промпты - только после чтения seedance-доков, ничего по памяти;
- **фото и видео генерю я** (Higgsfield CLI); видео-промпты - только после чтения skill `seedance`, модель под клип - по таблице цен в `02_higgsfield-routing.md`;
- каждый кадр - поштучно, self-QC через Read скачанного файла; принятый - через `cli.js accept` (сам переедет в `<campaign>/firstframes/` и запишется в шот);
- перед генерацией с рефом - проверить, что файл-реф существует (`[ -e ]`);
- bash с длинным `--prompt` - ОДНОЙ строкой; malformed tool-call - чисто переотправить один раз (полные правила - `CLAUDE.md` проекта, секция HARNESS);
- **медиа кампаний в git не коммитим** - в репо только тулза и текстовое состояние (`storyboard.json`, `canvas.json`, `RUN.md`, `PROGRESS.md`, `STORYBOARD.md`, `ENV-LOCK.md`, `TROUBLESHOOT.md`, `seedance-prompts.md`, `MANIFEST.md`); кадры/видео/инбокс/рефы и `.bus/`, `.history/` - в `.gitignore`, никогда не `git add -f`.

## Шаг 0.5 - Поднять тулзу и включить инбокс (молча, до опросника)

```
cd <ai-visual-root> && git pull
bash <ai-visual-root>/tools/storyboard/launch.sh          # сервер :4646 + UI (если уже поднят - просто откроет)
node <ai-visual-root>/tools/storyboard/cli.js status      # кампания, инбокс, очередь заявок
```
Дальше по ходу сессии - `cli.js intake to <кампания>`, если работаем не с той, что подхватилась.

**Пока сессия идёт, ~/Downloads НЕ используем как staging.** Перехват включён: всё скачанное медиа
уезжает в `<campaign>/inbox/`. Результаты Higgsfield CLI забираю сам, минуя Downloads:
`node cli.js grab <url> --as <имя>` -> файл сразу в инбоксе.

## Шаг 0.6 - Транскрипция (вести ВСЮ сессию, не задним числом)

В каждой кампании - `<campaign>/TRANSCRIPT.md`, живой журнал работы. Нет файла - завести сразу, при первом же действии.

**Что писать (после КАЖДОЙ итерации кадра, сразу за вердиктом, а не пачкой в конце):**
- **запрос пользователя** - дословно или максимально близко, включая резкие формулировки: в них диагноз;
- **мой reasoning** - почему выбрал такой ход, какую гипотезу проверял, что считал риском;
- **модель и флаги** - `<job_set_type>`, `--aspect_ratio`, `--resolution/--quality`, какие рефы и в каком порядке;
- **промпт** - целиком для принятых кадров; для отклонённых достаточно ключевых блоков и того, какие 1-2 фактора менял;
- **результат и вердикт** - что вернулось, что я увидел на self-QC, что сказал пользователь, приняли или нет;
- **уроки** - приёмы, которые сработали или провалились, в формулировке, годной для переноса в скилл.

**Зачем:** промпты и находки иначе растворяются в чате, а сессия обрывается на `/compact`. `TRANSCRIPT.md` - источник для апдейта `ai-visual` (`01_prompt-craft.md`, `02_higgsfield-routing.md`) и `ENV-LOCK.md` кампании.

**Git:** текстовый файл, коммитим вместе с остальным состоянием кампании.

## Шаг 0.7 - Встать в луп на заявки из тулзы

Кнопки в UI (перегенерить кадр · оживить · обсудить · разбери инбокс) - это **вызов меня в чат
по конкретному кадру**, а не команда на исполнение. Держи ожидание В ФОНЕ, чтобы пользователь мог параллельно писать:

```
node <ai-visual-root>/tools/storyboard/cli.js wait --timeout 900   # run_in_background: true
```

Команда завершается, как только пользователь нажал кнопку, - я просыпаюсь с заявкой. Дальше:
1. `cli.js claim <id>` - взял.
2. Посмотреть кадр (`Read` файла `payload.firstFrame`) и **говорить в чат** - держа этот кадр в голове.
3. Работать по итогам разговора, когда пользователь дал отмашку.
4. `cli.js done <id> --reply "итог"` - виден на карточке кадра. Снова поставить `wait` в фон.

Если `wait` вернул `{"idle":true}` - просто перезапустить, пока пользователь работает в тулзе.

### Главное правило кнопок
**Нажатие = вызов в чат, а не команда «исполняй».** Не лезть в Higgsfield, не подтягивать скиллы,
не писать промпты в момент нажатия. Сначала посмотреть кадр и обсудить его словами. Генерация,
skill `seedance`, правка json - только после явной отмашки пользователя в чате.

**Что означает каждая кнопка (как повод для разговора):**
- `regen` - «этот кадр меня не устраивает»: посмотреть его, сказать, что вижу, спросить/предложить,
  что менять. Гнать - после «ок». Готовое: `cli.js grab <url>` -> `cli.js accept <файл> --shot <id> --prompt "..." --model <модель>` (`--star`, если это новый первый кадр).
- `animate` - «пора думать про движение этого кадра»: обсудить, что вообще должно двигаться и почему.
  Промпт писать только после решения - и только прочитав skill `seedance` + `00_seedance-rules.md` + модули,
  затем `cli.js set <id> --video-prompt "..." --status prompt-ready`. Видео по промпту гонит пользователь - не я.
- `discuss` - разговор по сцене. Выводы фиксировать `cli.js set <id> --note "..."`.
- `palmier-push` - приходит, только если Palmier не ответил серверу: импортировать клипы из
  `<campaign>/palmier/` через MCP `palmier-pro` самому (skill `palmier-edit`), затем проставить статусы.
- `sort-inbox` - разобрать инбокс: посмотреть файлы (Read), разложить по кадрам через `accept --shot`,
  мусор - в `.trash`, спорное - оставить и спросить.

## Шаг 1 - Опросник (через AskUserQuestion, ОДНИМ вызовом, 4 вопроса)

1. **Режим** - `Новая кампания (с нуля)` · `Продолжить существующую` · `Клиентский заказ (интейк)`
2. **Этап сегодня** - `Интейк/смета` · `Первые кадры` · `Утверждение кадров клиентом` · `i2v-промпты` · `Монтаж` · `Сдача` · `Весь цикл`
   (в AskUserQuestion максимум 4 опции - показывай те, что подходят выбранному режиму)
3. **Формат кадра** - `4:3` · `16:9` · `9:16` · `1:1`
4. **Качество** - `2k` · `4k`

## Шаг 2 - Ветвление по ответам

- **Новая кампания:** добери бриф словами (не опросником): мотив/концепт, мир/локации, материалы или луки, длина ката, референс-кампания, бренд-плейсхолдер. Создай папку `<ai-visual-root>/<slug>/` с `RUN.md` + `PROGRESS.md` по конвенции (`03_pipeline.md`).
- **Клиентский заказ:** работаем по `04_client-workflow.md`. Заводим кампанию как обычно + папку `<ai-visual-root>/<slug>/client/` из шаблонов `<ai-visual-root>/client/templates/` (`INTAKE.md`, `SCOPE.md`, `DELIVERY.md`). Сначала анкета (5 обязательных полей: продукт · формат и площадка · рефы «нравится/НЕ нравится» · дедлайн · кто утверждает), потом объём и цена, и только после письменного «да» - производство. **Ворота: слова подписаны до кадров, кадры подписаны до i2v.**
- **Продолжить:** кампания из `$ARGUMENTS` (если пусто - спроси одной строкой или возьми последнюю активную, по умолчанию `second-nature`). Прочитай `<ai-visual-root>/<кампания>/RUN.md` (+ `PROGRESS.md`, `seedance-prompts.md`; если есть - `ENV-LOCK.md` и `TROUBLESHOOT.md`), **сам определи, где мы встали**, и дай TL;DR: «мы тут -> следующий шаг X».

## Шаг 3 - Работай

Если заказ клиентский - сверься с воротами (`04_client-workflow.md`): подписан ли объём, подписаны ли кадры. Не подписано - сначала закрываем ворота, потом генерим.

Зафиксируй выбранные формат и качество как параметры сессии (`--aspect_ratio <формат>`, `--quality 2k`/`--resolution <качество>` - НЕ хардкодить 4:3). Предложи конкретный следующий шаг и приступай.

## Дефолты

- CLI: `higgsfield` (тариф ultra). Результат генерации -> `cli.js grab <url>` в `<campaign>/inbox/`, принятое -> `cli.js accept ... --shot <id>` (переедет в `firstframes/` и станет вариацией шота). ~/Downloads больше не staging.
- **Сториборд-приложение:** `<ai-visual-root>/tools/storyboard/` (`launch.sh` -> http://127.0.0.1:4646) - статусы кадров, промпты и вариации веду через `cli.js` (пишет через сервер, правки пользователя в UI не затирает). Одобренные клипы -> Palmier кнопкой **Palmier** (сервер импортирует сам; набор - `<campaign>/palmier/`).
- **Утверждение кадров клиентом:** `node <ai-visual-root>/tools/storyboard/cli.js approval --campaign <slug> --client "Бренд" --project "Название" --due <дата>` -> `<campaign>/client/approval-<дата>.html` - самодостаточная страница (картинки внутри, ноль внешних запросов), уходит клиенту письмом. Проверить `skipped` в выводе перед отправкой. Ответ клиента сохранить дословно в `client/reply-<дата>.md` и разнести пошотно (`cli.js set <id> --note "правка клиента: ..."`). `approval-*.html` - в git-игноре, как медиа.
- **Журнал замечаний:** каждое замечание клиента - в `<ai-visual-root>/client/FEEDBACK-LOG.md`; всплыло дважды - чиню выше по потоку (анкета / кат-лист / бриф-блок промпта).
- **Видео: кадр -> промпт на согласование -> запуск.** Промпт показывать пользователю целиком в чате и ждать «ок» ПЕРЕД генерацией - всегда, даже если он сказал «на твоё усмотрение» или «быстрее» (это про выбор кадра, не про пропуск ворот).
- **Видео - строго ПО ОДНОМУ клипу**, не пачкой: сгенерил -> показал пользователю -> принял или забраковал -> только потом следующий. Роль кадра (старт через `--start-image` или финал через `--end-image`) решается для каждого кадра отдельно, общего правила нет. Уроки по движению и блок «фон намертво» - `03_pipeline.md` -> «Видео: по одному клипу».
- **Имена файлов = адрес шота:** `firstframes/<shotId>__v<N>__<модель>.png` (v1 - принятый). `refs/` - рефы, `inbox/` - только транзит, `.trash/` - снятое. После каждой серии приёмок и ПЕРЕД показом холста пользователю гонять `node <ai-visual-root>/tools/storyboard/tidy.js` - переименует по конвенции, починит битые ссылки на холсте, обновит `firstframes/MANIFEST.md`. Полное правило - `03_pipeline.md` -> «Хранение и имена файлов».
- **Промпты в json:** `framePrompt` - промпт кадра (t2i/i2i), `prompt` - i2v-промпт. Вариация = объект `{file, prompt, model, refs, jobId, verdict, note, ts}`; `verdict`: `new|accepted|rejected|parked`.
- Модель Higgsfield роутится автоматически под задачу (портрет / деталь-кроп / overhead) - см. `02_higgsfield-routing.md`. Монтаж - skill `palmier-edit`.
- **Одна модель на связку кадров.** Кадры, которые в кате стоят рядом и делят среду (проходка + peek + станции одной локации), гнать ОДНОЙ моделью - иначе цвет, фактура и вид среды плывут между планами. Сначала пытаться попасть в реф на модели связки, с явным упором на реф; не выходит - возвращаться к модели, на которой связка начиналась, а не менять её посреди серии.
- **Git:** тулза `tools/storyboard/` и текстовое состояние кампаний - в репо проекта; пиксели - нет (правила и причина: `tools/storyboard/README.md` -> «Что в git, а что нет»). В конце сессии на «закоммить и запушь» - `git add -A` с работающим `.gitignore`, кадры не форсить.
- Главное правило качества: материал = сконструированный couture-наряд на модели, не плоть и не абстрактный swatch.
